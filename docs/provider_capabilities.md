## 一、厂商功能与技能全景深度剖析

### 1.1 通义千问 (Tongyi Qianwen / 阿里巴巴)

作为阿里巴巴旗下的旗舰级大模型平台，通义千问在网页端（[qianwen.com](https://www.qianwen.com)）和移动端布局了极具平台化、超级助手化的功能矩阵。

#### 1. 联网与时效性检索
* **普通联网搜索 (Web Search)**：支持全网高时效性信息检索，并在正文以角标 `[1]`, `[2]` 形式标注溯源引用，展示来源网站标题与原链。
* **深度搜索 (Deep Search)**：自动将用户的复杂模糊问题分解为多个子查询，执行多阶段检索并交叉比对，最终输出结构化综述报告。
* **阿里电商与生活场景打通**：与淘宝天猫、高德等阿里生态结合，支持检索消费导购、店铺信息与实时生活资讯。

#### 2. 推理与深度思考 (Reasoning & CoT)
* **Qwen3.7-Max / QwQ 深度思考**：支持长思维链（Chain of Thought）显式呈现，支持展示逻辑推理步骤、算法反思与错误自我修正。
* **思维过程折叠交互**：前端支持折叠/展开“思考过程”，输出最终结论，思考消耗时间实时可见。

#### 3. 多模态能力 (看/听/画/说)
* **图像理解 (Qwen-VL / Vision)**：
  - 支持多图同时上传识别。
  - 具备极高准确率的 OCR 文字提取、复杂表格解析、手写笔记识别、公式提取（LaTeX 导出）。
  - 支持“看图写代码”（根据网页设计图、UI 截图直接生成前端 HTML/CSS/React 代码）。
* **图像生成 (通义万相 / Wanx)**：
  - 深度集成通义万相文生图大模型，支持多样化艺术风格（水彩、写实、赛博朋克、古风国潮、3D 渲染）。
  - 支持在对话中直接输入绘图提示词生成高清图像，并提供“重新生成”、“灵感修饰”等功能。
* **语音输入与 TTS 播报**：
  - 网页端与 App 端支持流式语音输入转文字。
  - 支持多款自然拟真音色朗读回复，包含情感起伏调节。
* **视频与音乐衍生能力**：
  - 集成通义万相图生视频、文生视频功能。
  - 通义听悟能力集成：支持长音视频文件解析、音视频摘要生成、发言人分离识别。

#### 4. 文档与数据分析 (通义智文)
* **极大多格式文件解析**：支持 PDF、Word (docx/doc)、Excel (xlsx/xls)、PPT (pptx/ppt)、TXT、Markdown、EPUB、CSV、代码文件。
* **超长文本处理**：具备 1000 万字级别的单文档解析与多文档跨库对比能力。
* **结构化速读与图表提取**：
  - 自动生成长文档脉络大纲、核心要点摘要。
  - 关键信息提取、对比表格生成，并支持一键生成思维导图。
* **代码解释器 (Code Interpreter / Python 沙箱)**：
  - 支持云端自动运行 Python 代码。
  - 支持上传 CSV/Excel 进行数据清洗、描述性统计、绘制 Matplotlib/Seaborn 图表并直接下载。

#### 5. 智能体与工具生态
* **通义百宝箱 (官方应用广场)**：包含数百款开箱即用的专业智能体，涵盖职场办公、学术论文阅读、创意写作、代码编写、法律问答、求职面试模拟等。
* **自定义智能体 (Agent Builder)**：支持用户零代码创建专属智能体，支持配置个性化 Prompt、上传专属私有知识库（RAG）、接入外部自定义 API Actions。

#### 6. 会话管控与隐私实用工具
* **临时会话模式 (Temporary Session)**：协议层显式支持 `temporary: true`，开启后会话不计入个人历史记录，不沉淀聊天数据，杜绝隐私泄漏。
* **会话管理**：支持会话置顶（Pin）、分类归档、关键词跨会话历史全文检索、一键导出长图/Markdown、生成外部公开分享链接。

### 1.2 DeepSeek (深度求索)

DeepSeek 网页端（[chat.deepseek.com](https://chat.deepseek.com)）秉承极客风格与极简主义，不追求繁杂的商业化生态，专注于将**极致推理**、**高质代码**与**极速检索**做到纯粹。

#### 1. 联网与时效性检索
* **联网搜索 (`search_enabled: true`)**：
  - 具备独立网页抓取与索引重排系统，检索响应极为迅速。
  - 结构化引用：在回答中自动插入引用索引编号，并在正文末尾呈现透明清晰的抓取网页标题、域名与点击跳转卡片。

#### 2. 推理与深度思考 (Reasoning & CoT)
* **DeepSeek-R1 (深度思考 `thinking_enabled: true`)**：
  - 核心标杆功能，原生集成强化学习驱动的 DeepSeek-R1 完整长思维链。
  - SSE 数据流原生输出 `fragments` 片段（区分 `THOUGHT` 思考流与 `RESPONSE` 回复流）。
  - 前端以浅灰色卡片展示完整的思维反思过程，包含探索不同解法路径、自我质疑、数学演算与边界验证。

#### 3. 多模态能力
* **极简纯文本定位**：截至目前，DeepSeek 官方 Web 端（chat.deepseek.com）聚焦于纯文本与代码领域，尚未将开源的 Janus / Janus-Pro 多模态生成模型集成到生产环境对话框中。
* **无语音/绘画功能**：不提供文生图、高拟真 TTS 朗读或视频生成功能。

#### 4. 文档与代码分析
* **文件上传 (`ref_file_ids: []`)**：
  - 支持上传 PDF、TXT、DOCX、代码仓库文本等多种常见文档。
  - 后台对文档进行分块与上下文检索，针对长文档做精准代码走查、论文释义与逻辑总结。
* **代码编写与审查**：
  - 依托强大的 DeepSeek-Coder 架构，具备顶尖的代码补全、排错与重构能力。
  - 前端具备优良的代码块语法高亮与一键复制代码体验（无云端沙箱在线执行能力，代码需本地运行）。

#### 5. 智能体生态
* **纯粹无智能体广场**：未设立公域 Bot 广场，不提供社区用户自定义 Agent、知识库插件等附加功能，界面干净清爽。

#### 6. 会话管控与安全机制
* **会话流转与管理**：
  - 会话多级追踪机制（通过 `chat_session_id` 与 `message_id` 双指针维持上下文树形分支）。
  - 支持历史会话查看、重命名、单项删除。
* **防御性 PoW 挑战 (Proof-of-Work)**：
  - 前端集成自研 WebAssembly 模块（`DeepSeekHashV1`），每次请求需在本地完成 SHA3 哈希碰撞求解，携带 `x-ds-pow-response` 请求头以抵御机器人滥用。

### 1.3 豆包 (Doubao / 字节跳动)

豆包（[www.doubao.com](https://www.doubao.com)）是字节跳动倾力打造的国民级 AI 助手，依托抖音、今日头条的内容与多媒体技术积累，在**拟真人机交互**、**多模态视听创想**和**智能体社区**上处于领先地位。

#### 1. 联网与时效性检索
* **生态级联网搜索**：整合头条搜索与全网资讯，实时抓取新闻热点、知乎科普、自媒体资讯。
* **深度搜索 (Deep Research)**：支持“深入研究”模式，自动展开全网多角度调查，生成包含详细数据、图表和引用来源的长文调研报告。

#### 2. 推理与深度思考 (Reasoning & CoT)
* **分级深度思考能力**：
  - 支持两档思考等级：常规深度思考（`need_deep_think: 1`）与 Expert 专家级思考（`need_deep_think: 3`）。
  - SSE 流中通过独立的 `thought_block`（block_type 特殊标记）向客户端流式输出思维链，包含问题的拆解视角、分步计算与校验过程。

#### 3. 多模态能力 (看/听/画/说)
* **图像理解 (Vision)**：
  - 支持多格式图片上传，支持拍照解题、物体识别、表情包解读、图表转文字。
* **高质量图像生成 (文生图)**：
  - 基于字节自研扩散模型与剪映视觉算法，支持生成高美感艺术图、写实摄影、动漫二次元、电商商品展示图等。
  - 支持中文提示词直接唤醒生图，提供“重绘”、“风格变换”等微调工具。
* **超高拟真 TTS 语音朗读与全双工通话**：
  - 业内顶尖水准的语音合成引擎，提供数十种极其拟真、带有呼吸声与真实语调起伏的角色音色（活泼少女、沉稳青年、温柔姐姐、东北话/四川话等方言）。
  - App 端与网页端支持全双工即时语音通话，支持随意插话打断。
* **音乐与播客创作**：
  - **AI 音乐创作**：支持根据用户输入的歌词或主题，自动生成旋律、伴奏并由 AI 歌手演唱。
  - **AI 播客生成**：支持将输入的文章、网页或文档一键转化为双人对谈式音频播客。

#### 4. 文档与数据分析
* **多格式文件极速解析**：支持 PDF、Word、Excel、PPT、EPUB、TXT、代码源文件等。
* **阅读助手与表格提炼**：
  - 提取文献核心论文摘要、文献答疑。
  - 自动将杂乱非结构化内容整理成规范的 Markdown 表格或数据图表。

#### 5. 庞大的智能体社区 (Bot 生态)
* **海量智能体应用广场**：
  - 涵盖生活陪伴（英语口语陪练、夸夸群、情感树洞）。
  - 涵盖职场生产力（公文写作、爆款小红书文案、短视频脚本、周报生成器、简历修改）。
  - 虚拟角色互动（名著角色、历史人物、动漫角色扮演）。
* **自定义 Agent 工作台**：支持用户自定义 Bot 名称、头像、音色绑定、开场白、系统提示词与私有文档知识库。

#### 6. 会话管控与隐私
* **无痕临时会话**：支持快速开启临时聊天模式，不保存聊天历史，关闭页面即销毁。
* **会话组织**：支持多会话置顶、会话分类、会话批量清理（`batch_del_user_conv` 协议）、消息分支回滚与长图分享。

## 三、网关集成与协议映射可行性分析

本项目是一个将网页端反向工程调用转译为标准 **OpenAI Chat Completions (`/v1/chat/completions`)** 与 **Anthropic Messages (`/v1/messages`)** 协议的本地网关。

在此架构下，如何最大化利用各平台上诉非对话技能？以下是详细的可行性评估与设计方案。

### 3.1 本仓库已支持能力现状

当前仓库已具备良好的模块化基础，已稳定支持的能力包括：
1. **深度思考 (Thinking / Reasoning)**：
   - 通义千问���支持路由到 `Qwen3.7-Max` 等强推理模型。
   - DeepSeek：将客户端 `thinking: true` 映射到网页端 `thinking_enabled: true`。
   - 豆包：将客户端 `thinking: true` 映射到网页端 `need_deep_think: 1` 或 `need_deep_think: 3`（Expert 模式）。
2. **联网检索 (Web Search)**：
   - 在 `ChatCompletionRequest` 中透传 `search: true`，分别激活 Qwen 的 `deep_search: "normal"` 和 DeepSeek 的 `search_enabled: true`。
3. **会话持久化与多轮续聊 (Conversation Continuity)**：
   - 响应末尾回传 `conversation_id`，客户端再次请求传入该 ID 即可在网页端保持会话上下文。
4. **合成工具调用 (Synthetic Tool Calling)**：
   - 在 Anthropic 兼容层（`anthropic_compat.py`）中，把客户端声明的 `tools` 注入 System Prompt，并流式拦截模型吐出的 ````tool_call` 代码块，转译为标准的 Anthropic `tool_use` content blocks。

---

### 3.2 易于标准协议化扩展的能力（第一梯队）

以下功能与标准 OpenAI/Anthropic 协议契合度极高，且上游接口具备对应支持，适合在网关中优先落地：

#### 1. 深度思考过程的规范化分离输出 (Reasoning Content Separation)
* **行业标准**：
  - OpenAI 规范（针对 DeepSeek-R1 / o1）：在 chunk 中输出 `delta.reasoning_content`。
  - Anthropic 规范：在流式中输出 `content_block_start`（`type: "thinking"`）与 `content_block_delta`（`type: "thinking_delta"`）。
* **技术可行性**：
  - **DeepSeek**：SSE 流已包含 `type == "THOUGHT"` 的独立片段，极易分流。
  - **豆包**：具备独立的 `thought_block`，解析其增量文本后直接映射到 `reasoning_content`。
  - **通义千问**：解析其返回结构中带思考标记的 message 块。
* **落地价值**：
  - 使得接入本网关的第三方客户端（如 Cherry Studio, NextChat, Chatbox, Cursor）能够像调用官方 API 一样，优雅地将“思考过程”收拢到折叠框中，提升交互体验。

#### 2. 多模态图像输入 (Vision Multimodal Input)
* **行业标准**：
  - OpenAI 格式：`content: [{"type": "text", "text": "..."}, {"type": "image_url", "image_url": {"url": "data:image/jpeg;base64,..."}}]`。
  - Anthropic 格式：`content: [{"type": "image", "source": {"type": "base64", "media_type": "...", "data": "..."}}]`。
* **技术可行性**：
  - **通义千问**：其网页版具备文件/图片上传 API，上传后获得 `file_id`，插入消息的 `meta_data` 或多模态 `content` 块中。
  - **豆包**：其 payload 结构中包含 `block_type`，支持图片 block（`image_block`）。
* **工程路径**：
  - 网关在收到包含 base64 / URL 的图片请求时，先调用网页端对应的图片上传/预检接口获取远程标识，随后组装多模态消息体发送。

#### 3. 隐私模式 / 临时会话开关 (Ephemeral Sessions)
* **实现方式**：
  - 在 API 请求的 `extra_body` 中接收 `temporary: bool = False`。
  - **通义千问**：直连网页端 payload 的 `temporary: true`，对话完毕后网页端不留下任何会话历史。
  - **豆包**：传入临时会话专用 option 字段。
* **落地价值**：
  - 自动化脚本、单元测试或高频爬虫调用时，避免用户的网页端被几百条无意义的碎片会话刷屏。

#### 4. 标准文生图端点 (`POST /v1/images/generations`)
* **行业标准**：
  - 兼容 OpenAI 标准 DALL-E 接口：`POST /v1/images/generations`，输入 `prompt`, `n`, `size`，返回 `data: [{"url": "..."}]`。
* **技术可行性**：
  - **豆包**与**通义千问**均拥有顶级的 Web 生图接口。
  - 网关只需增加该路由，调用豆包/通义万相的生图 API，等待 SSE 或长轮询返回图片 CDN URL，再封包成 OpenAI 图像响应结构。

### 3.3 需定制接口或深层逆向的能力（第二梯队）

以下功能虽然具有吸引力，但由于缺乏统一的开放标准，或与特定 UI 界面深度绑定，建议以扩展端点或实验性功能实现：

#### 1. 高拟真语音合成端点 (`POST /v1/audio/speech`)
* **对应能力**：利用豆包顶尖的自然音色 TTS 朗读功能。
* **协议映射**：映射为 OpenAI `/v1/audio/speech` 规范（输入 `input`, `voice`, `model`，返回音频二进制流）。
* **工程难点**：需抓取豆包网页端发起 TTS 请求时的签名、分片传输协议及 WebSocket/SSE 音频流解码。

#### 2. 文档与超长文件阅读解析 (`POST /v1/files`)
* **对应能力**：利用通义智文或豆包长文档解析引擎。
* **协议映射**：可参照 OpenAI Assistants API 的 `/v1/files` 端点。客户端上传 PDF 后，网关将其转传到通义/豆包存储桶，并在对话中附加 `file_ids`。
* **降级替代方案**：当前本地网关更推荐由客户端本地将文本或代码提取出来直接拼入 prompt，无需依赖厂商文件上传服务的额外网络握手。

#### 3. 云端 Python 沙箱执行结果透传
* **对应能力**：通义千问的代码解释器。
* **工程难点**：云端执行生成的交互式图表或终端输出是以特殊的前端组件卡片渲染的，逆向解析该组件并将输出规范化转为标准文本或图片 base64 成本较高。

### 3.4 反向工程边界与稳定性风控建议

将网页端非对话能力接入网关时，需关注以下风控边界：

1. **反爬与安全挑战 (WAF / PoW)**：
   - **通义千问**：存在阿里集团统一的高灵敏度 WAF（`RGV587_ERROR`），大文件上传或高并发调用极易触发前端滑块验证码。本仓库的 `login.py qwen` 提供了弹窗人机校验支持，应合理控制调用频率。
   - **DeepSeek**：全量实施本地 WASM PoW 计算。当前本仓库使用 `wasmtime` 成功在本地解决了 `DeepSeekHashV1` 计算难题（`providers/deepseek/pow.py`），运行稳定。
   - **豆包**：具备严格的设备指纹与 `s_v_web_id` 滑块风控，已通过模拟桌面客户端（`client_platform: pc_client`）规避大部分 Web 端的 `a_bogus` 算法，但频繁上传敏感文件仍有降级风险。
2. **Cookie 与凭证有效期治理**：
   - 网页端的 Session 生命周期一般在数小时至数天不等。本项目在 `lifespan` 中设置了后台守护线程（超过 6 小时自动静默刷新），有效保障了长期无人值守运行的稳定性。
3. **接口版本变动防护**：
   - 网页端前端打包几乎每周更迭，非标准接口（如百宝箱插件、图片生图接口）的 payload 结构可能随时微调，因此网关设计应遵循“**核心文本与推理能力求稳，多模态与生图能力渐进式扩展**”的原则。
