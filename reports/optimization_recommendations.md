- **预期收益**: 掐断一条**每条请求都在发生**的无效触碰通道：整环处于长效避让时，不再为每个客户端请求把五个已被风控标记的节点逐个打满（零上游调用），从而不再向「自动化尝试」的风控评分里持续投喂证据、不再延长封禁窗口——直接服务于「deepseek 已被封、不得加重其余四家风控」的硬约束。可用性按设计零回归：短冷却的 demote-only「最后一搏」语义逐字节保持不变，且由阈值夹逼**结构性地**保证短冷却永远不可能被误判为长效避让（测试证明真空带存在而非假设）。改派路径已被证明是真正的零触碰——长效避让节点的剩余冷却只允许衰减、不得延长。运维可观测且可操作：诊断暴露 enabled/threshold_seconds/avoiding/stats，快速失败报文逐节点给出成因与剩余小时数及重登/静默等待的分别指引，档案姿态与派发事实一致（不再自称可派发）。

用唯一能真正证明它的方式证明：**篡改那唯一一份闸门定义**（谎报一个健康节点被阻断），断言真实派发随之拒绝该节点——若派发循环哪天退回自带副本，它就会无视篡改照常派发，该用例立即变红。同批另修一处工程缺陷：run.sh 原先执行 .venv/bin/uvicorn，而 venv 被移动/复制后控制台脚本里固化的创建时绝对解释器路径会失效（本机实测 bad interpreter: No such file or directory），现改为解析出真正能 import uvicorn 的解释器（项目 venv 优先、系统 Python 兜底）并以 python -m uvicorn 启动，虚拟环境与真实环境皆可运行。
- **预期收益**: 把「避让声明一定生效」从**测试保证**升级为**结构保证**：闸门顺序只有一份定义，预演与派发不可能各自偏离，因此这类「文档/预演说会避让、实现仍派发」的缺陷从「靠测试兜住」变成「靠结构不可能发生」——本项目的同类缺陷（OPT-021/026/027/029/031 各自修过的那些）从此少了一整条复发路径。运维的显式禁用声明第一次在派发边界上构成性生效：被 DISABLED_PROVIDERS 点名的节点在任何路径下都不会收到真实上游请求（改派或零上游快速失败），报文与 Anthropic 映射给出可操作的解除指引。可用性零回归：短冷却的最后一搏语义逐字节不变，禁用禁用集合的合并方向只会更保守，且「现读环境变量」的既有行为被显式保留并由用例锁住（tests/test_dispatch_gate.py 共 10 个用例，全量 36 个套件回归通过）。可观测性补齐：逐闸门拒载直方图让「谁在拒载」直接可见，预演条目不再因环级成因掩盖而丢失逐节点状态。工程侧：run.sh 对环境形态（虚拟环境 / 系统 Python、venv 是否被移动过）免疫，消除了「换个目录就起不来」这一与业务无关却能完全阻断验证的故障。
